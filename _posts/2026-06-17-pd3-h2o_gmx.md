## Overview

This post documents the complete pipeline for setting up a molecular dynamics
simulation of a **Pd₃ palladium nanocluster solvated in OPC water** using
GROMACS on the PARAM Shakti HPC cluster at IIT Kharagpur. The goal is a
reproducible, publication-quality NPT equilibration followed by a production
run, with every non-obvious decision explained and justified.

The pipeline covers:

1. Force-field file preparation and Packmol box packing with **fftool**
2. Correcting the raw GROMACS topology for **4-site OPC** (MW virtual site)
3. Fixing the **Lorentz-Berthelot mixing rule** for the Pd–Ow cross term
4. Inserting the MW dummy site into the coordinate file
5. **EM → NVT → NPT** sequential equilibration on PARAM Shakti
6. Automated post-run sanity checks and PBC correction

**System:** 1 Pd₃ cluster + 7,205 OPC water molecules, 60 × 60 × 60 Å cubic box,
298.15 K, 1 bar — total **28,823 atoms**.

## 2. Input Files

Two z-matrix (`.zmat`) and two force-field (`.ff`) files are required. The
key parameters for each component are listed below.

### Pd₃ force field (`pd3.ff`)

Palladium LJ parameters from the INTERFACE force field (Heinz 2008):

| Parameter | Value |
|-----------|-------|
| σ | 2.5114 Å |
| ε | 3.58509 kcal/mol (= 15.0039 kJ/mol) |
| Charge | 0.0 e |
| Pd–Pd bond | 2.676 Å (equilateral D₃h, DFT geometry) |

### OPC water force field (`opc.ff`)

OPC (Izadi & Onufriev 2014) is a 4-point water model. The
negative charge does **not** sit on the oxygen — it lives on a massless
virtual site (M-site) displaced 0.1594 Å off the oxygen along the
H–O–H bisector.

| Parameter | Value |
|-----------|-------|
| q(Ow) | 0.0 e |
| q(Hw) | +0.6791 e |
| q(MW) | −1.3582 e |
| r(OH) | 0.8724 Å |
| ∠HOH | 103.6° |
| d(OM) | 0.1594 Å |

> **Why OPC?** OPC reproduces bulk water density, diffusion coefficient, and
> dielectric constant simultaneously better than TIP4P or SPC/E, making it the
> preferred choice for solvation studies of metal nanoclusters.

## 3. Packing the Box with fftool + Packmol

### Step 1 — Generate per-molecule coordinate files

```bash
# The --box flag sets the cubic box edge in Å
# This pass generates pd3_pack.xyz and opc_pack.xyz
# It also writes a generic pack.inp — BACK UP your custom one first
cp pack.inp pack.inp.mine
fftool 1 pd3.zmat 7205 opc.zmat --box 60.0
cp pack.inp.mine pack.inp   # restore custom packing logic
```

### Step 2 — Custom `pack.inp`

The custom `pack.inp` places Pd₃ at the exact box centre (30, 30, 30 Å) and
enforces a 5.5 Å exclusion sphere around it so no water is placed inside the
first coordination shell:

```text
tolerance 2.0
filetype xyz
output simbox.xyz

structure pd3_pack.xyz
  number 1
  center
  fixed 30.0000 30.0000 30.0000 0.0 0.0 0.0
end structure

structure opc_pack.xyz
  number 7205
  inside box 1.5000 1.5000 1.5000 58.5000 58.5000 58.5000
  outside sphere 30.0000 30.0000 30.0000 5.5
end structure
```

The 1.5 Å buffer on each face prevents water from overlapping with the periodic
image of the opposite face.

### Step 3 — Run Packmol

```bash
packmol < pack.inp
```

On success Packmol prints `Success!` and writes `simbox.xyz`.
Verify the atom count:

```bash
head -2 simbox.xyz
# Expected: 21618  (3 Pd + 7205 × 3 OPC sites)
```

### Step 4 — Generate GROMACS files

```bash
fftool 1 pd3.zmat 7205 opc.zmat --box 60.0 --gmx
```

fftool writes `field.top`, `run.mdp`, and `config.pdb`.

> **Note:** At this stage `field.top` has two critical errors that must be
> fixed before grompp will produce a physically correct simulation. Both are
> addressed in the next section.

## 4. Correcting the Topology (`field.top`)

fftool produces a raw topology with two problems for this system:

1. **Wrong mixing rule** (`comb-rule 3` geometric σ instead of `comb-rule 2`
   Lorentz-Berthelot for the Pd–Ow cross term).
2. **3-site OPC** — the negative charge is left on the oxygen atom instead of
   being moved to the MW virtual site.

The corrected `field.top` is reproduced in full below with every column and
flag documented inline.

```

; GROMACS internal units: length=nm, energy=kJ/mol, mass=u, charge=e
; Ref: GROMACS Reference Manual > Topologies > Parameter files
;      https://manual.gromacs.org/current/reference-manual/topologies/parameter-files.html

; nbfunc   comb-rule   gen-pairs   fudgeLJ   fudgeQQ
; nbfunc 1  = Lennard-Jones
; comb-rule 2 = arithmetic σ_ij=(σ_i+σ_j)/2, geometric ε_ij=√(ε_i·ε_j)
;              → Lorentz-Berthelot, correct for INTERFACE FF + OPC (AMBER lineage)
; comb-rule 3 (fftool default) = geometric σ too → WRONG for this system
  1        2           yes         0.5       0.5

[ atomtypes ]

; ptype A = normal atom. charge here is default/fallback; per-atom [ atoms ]

; sigma and epsilon interpreted as V and W columns under comb-rule 2.

; nrexcl 3: exclude non-bonded interactions up to 3 bonds apart.
; With constraints (not bonds), exclusions are traced through constraint
; connections — all Pd-Pd pairs are auto-excluded.
pd3       3

[ atoms ]
;  nr   type  resnr  residue  atom  cgnr     charge

    1   Pd1      1   pd3      Pd1     1     0.000000
    2   Pd2      1   pd3      Pd2     2     0.000000

; Three constraints on three atoms → fully rigid equilateral triangle (D3h).

    2    1     1     0.26760

    2    1    3
    3    1    2

; handles all intramolecular non-bonded interactions.
OPC       2

; Net molecular charge: 0 + 2(+0.6791) + (-1.3582) = 0. System neutral.
    1   Ow       1   OPC      O       1     0.000000   15.99900
    2   Hw       1   OPC      H1      1     0.679100    1.00800
    3   Hw       1   OPC      H2      1     0.679100    1.00800
    4   MW       1   OPC      MW      1    -1.358200    0.00000

[ settles ]
;  OW   func    doh(nm)    dhh(nm)
; SETTLE analytically rigidifies water using doh and dhh.
; dhh encodes the HOH angle: dhh = 2·doh·sin(θ/2) = 2(0.08724)sin(51.8°) = 0.13713 nm
; SETTLE fixes both bond lengths AND the angle — replaces harmonic [ angles ].
    1    1      0.08724    0.13713

[ exclusions ]

    1    2    3    4
    2    1    3    4
    3    1    2    4
    4    1    2    3

; This places MW 0.1594 Å from O on the H-O-H bisector (OPC definition).
; mdrun rebuilds MW's position every step — coordinate file value is a placeholder.
; site  ai   aj   ak  func      a           b
    4    1    2    3    1      0.147722    0.147722

; Order and counts MUST match the coordinate file exactly.
; Pd3 was packed first by Packmol.
pd3       1
OPC       7205
```

### Why comb-rule 2 matters for Pd–Ow

Under comb-rule 2 (Lorentz-Berthelot), the cross terms are:

$$
\sigma_{ij} = \frac{\sigma_i + \sigma_j}{2}, \quad
\epsilon_{ij} = \sqrt{\epsilon_i \cdot \epsilon_j}
$$

Under comb-rule 3 (OPLS geometric), both are geometric means:

$$
\sigma_{ij} = \sqrt{\sigma_i \cdot \sigma_j}
$$

For Pd (σ = 0.25114 nm) and Ow (σ = 0.31666 nm), this gives:

| Rule | σ(Pd–Ow) nm |
|------|------------|
| comb-rule 2 (LB, **correct**) | 0.28390 |
| comb-rule 3 (geometric) | 0.28217 |

A 0.0017 nm difference in σ shifts the Pd–Ow potential minimum depth and
position, altering the first solvation shell structure — the primary observable
in this study.

## 5. Inserting the OPC MW Virtual Site into the Coordinate File

fftool writes `config.pdb` with 3 sites per water (21,618 atoms). The topology
now expects 4 sites per water (28,823 atoms). The following Python script
inserts one MW placeholder atom after each water's H2, keyed on the residue
name `OPC` so it is safe to reuse for any solute:

```python
#!/usr/bin/env python3
"""
add_mw.py -- insert the OPC MW virtual-site atom into a packed PDB.
Usage: python3 add_mw.py config.pdb config_mw.pdb
"""
import sys

WATER_RES   = "OPC"
MW_NAME     = "MW"
ATOMS_PER_W = 3

inp = sys.argv[1] if len(sys.argv) > 1 else "config.pdb"
out = sys.argv[2] if len(sys.argv) > 2 else "config_mw.pdb"

def is_atom(l):   return l.startswith("ATOM") or l.startswith("HETATM")
def resname(l):   return l[17:20].strip()
def make_mw(o):   return o[:12] + (" %-3s" % MW_NAME) + o[16:]

out_lines = []; buf = []; n_water = 0; n_other = 0

def flush_water():
    global n_water
    if not buf: return
    if len(buf) != ATOMS_PER_W:
        sys.exit(f"ERROR: OPC residue had {len(buf)} atoms, expected {ATOMS_PER_W}")
    out_lines.extend(buf)
    out_lines.append(make_mw(buf[0]))   # MW placeholder at oxygen position
    buf.clear(); n_water += 1

with open(inp) as f:
    for raw in f:
        line = raw.rstrip("\r\n")
        if is_atom(line) and resname(line) == WATER_RES:
            buf.append(line)
            if len(buf) == ATOMS_PER_W: flush_water()
        else:
            flush_water()
            if is_atom(line): n_other += 1
            out_lines.append(line)
flush_water()

serial = 0
for i, l in enumerate(out_lines):
    if is_atom(l):
        serial += 1
        out_lines[i] = l[:6] + ("%5d" % (serial % 100000)) + l[11:]

with open(out, "w") as f:
    f.write("\n".join(out_lines) + "\n")

print(f"water residues     : {n_water}   (one MW added to each)")
print(f"non-water atoms    : {n_other}")
print(f"total atoms written: {serial}   (expected {n_other + n_water*4})")
```

Run and verify:

```bash
python3 add_mw.py config.pdb config_mw.pdb
# Expected output:
# water residues     : 7205   (one MW added to each)
# non-water atoms    : 3
# total atoms written: 28823  (expected 28823)

# Spot-check first water block — must be O, H1, H2, MW in that order
grep -m4 ' OPC ' config_mw.pdb
```

> **MW coordinate = oxygen position.** grompp/mdrun reconstruct MW's real
> position every step from the `[ virtual_sites3 ]` rule. The placeholder
> coordinate is never used in any force calculation.

## 6. Why Pd₃ Behaves as a Single Rigid Entity

The three `[ constraints ]` entries in the topology fully rigidify the cluster:

```
[ constraints ]
    2    1     1     0.26760   ; Pd2–Pd1  fixed at 0.2676 nm
    3    1     1     0.26760   ; Pd3–Pd1  fixed at 0.2676 nm
    2    3     1     0.26760   ; Pd2–Pd3  fixed at 0.2676 nm
```

Three distance constraints on three atoms uniquely fix the shape of the triangle.
No angle term is needed — once all three sides are fixed the angle is determined
implicitly. LINCS enforces these constraints at every step after the unconstrained
leap-frog update, resetting the Pd–Pd distances to exactly 0.2676 nm.

| Degree of freedom | Status |
|---|---|
| Pd–Pd bond lengths | Frozen at 0.2676 nm (LINCS) |
| Pd–Pd–Pd angles | Frozen at 60° (implicit from 3 fixed sides) |
| Internal vibration | Zero (no internal DOF remain) |
| Cluster translation | **Free** — COM moves under net solvent force |
| Cluster rotation | **Free** — torque from solvent rotates the body |

The cluster diffuses and tumbles in solution exactly as a real nanocluster would.
What is frozen is only its internal geometry, not its position in the box.

## 8. MDP Files — Equilibration Protocol

The protocol follows three sequential phases. The key design decisions across
all phases are consistent:

| Property | EM | NVT | NPT |
|---|---|---|---|
| `integrator` | `steep` | `md` | `md` |
| `pcoupl` | `no` | `no` | `Parrinello-Rahman` |
| `tcoupl` | N/A | `V-rescale` | `V-rescale` |
| `gen-vel` | N/A | `yes` | `no` |
| `continuation` | `no` | `no` | `yes` |
| `DispCorr` | `No` | `EnerPres` | `EnerPres` |
| `constraints` | `all-bonds` | `all-bonds` | `all-bonds` |

### 8.1 Energy Minimisation (`01_em.mdp`)

```ini
integrator            = steep
emtol                 = 1000.0        ; convergence: Fmax < 1000 kJ/mol/nm
emstep                = 0.01          ; initial step size [nm]
nsteps                = 50000         ; max steps (early termination expected)

cutoff-scheme         = Verlet
pbc                   = xyz
coulombtype           = PME           ; required for discrete MW charge
rcoulomb              = 1.2
ewald-rtol            = 1.0e-5
pme-order             = 4
fourierspacing        = 0.12

vdwtype               = Cut-off
vdw-modifier          = Potential-shift
rvdw                  = 1.2
DispCorr              = No            ; off: packed box density not yet converged

constraints           = all-bonds     ; includes Pd-Pd via LINCS + SETTLE water
constraint-algorithm  = LINCS
lincs-order           = 6             ; higher order for closed Pd3 triangle
lincs-iter            = 2
```

`DispCorr = No` during EM is intentional. The long-range dispersion tail
correction assumes a converged homogeneous liquid density. A freshly Packmol-packed
box has voids and an inhomogeneous density — applying the correction here would
give a nonsense pressure correction. It is switched on from NVT onward.

### 8.2 NVT Equilibration (`02_nvt.mdp`)

```ini
integrator            = md
dt                    = 0.002         ; 2 fs — safe with all-bonds constraints
nsteps                = 500000        ; 1 ns

coulombtype           = PME
rcoulomb              = 1.2
ewald-rtol            = 1.0e-5
pme-order             = 4
fourierspacing        = 0.12

vdwtype               = Cut-off
vdw-modifier          = Potential-shift
rvdw                  = 1.2
DispCorr              = EnerPres      ; tail correction on from NVT onward

; V-rescale correctly samples the canonical ensemble (Bussi et al. 2007).
; Separate groups prevent hot-solute/cold-solvent artefacts.
tcoupl                = V-rescale
tc-grps               = pd3  OPC
tau-t                 = 2.0  2.0
ref-t                 = 298.15  298.15

pcoupl                = no            ; FIXED volume: equilibrate T before P

gen-vel               = yes           ; fresh start after EM
gen-temp              = 298.15
gen-seed              = -1

constraints           = all-bonds
constraint-algorithm  = LINCS
lincs-order           = 6
lincs-iter            = 2
continuation          = no
```

### 8.3 NPT Equilibration (`03_npt.mdp`)

```ini
integrator            = md
dt                    = 0.002
nsteps                = 500000        ; 1 ns

coulombtype           = PME
rcoulomb              = 1.2
ewald-rtol            = 1.0e-5
pme-order             = 4
fourierspacing        = 0.12

vdwtype               = Cut-off
vdw-modifier          = Potential-shift
rvdw                  = 1.2
DispCorr              = EnerPres

tcoupl                = V-rescale
tc-grps               = pd3  OPC
tau-t                 = 2.0  2.0
ref-t                 = 298.15  298.15

; Parrinello-Rahman produces a correct NPT ensemble.
; The GROMACS manual explicitly states Berendsen does NOT.
pcoupl                = Parrinello-Rahman
pcoupltype            = isotropic     ; cubic box stays cubic
tau-p                 = 2.0           ; [ps] must be >> tau-t for P-R stability
ref-p                 = 1.0           ; [bar]
compressibility       = 4.5e-5        ; [bar-1] experimental value for water at 298 K

gen-vel               = no            ; velocities inherited from nvt.cpt
continuation          = yes           ; signals continuation to grompp

constraints           = all-bonds
constraint-algorithm  = LINCS
lincs-order           = 6
lincs-iter            = 2
```

> **Critical:** the NPT grompp call must pass `-t nvt.cpt` to inherit the
> thermally equilibrated velocities from NVT. Without this flag the NPT run
> starts from zero velocities, discarding the NVT equilibration entirely.

## 9. SLURM Submission on PARAM Shakti

All three phases are run inside a **single SLURM job** to avoid queue re-entry
delays and to ensure each phase inherits the exact checkpoint from the previous
one. The `set -e` directive in the script halts execution immediately if any
phase fails.

```bash
#!/bin/bash
#SBATCH --partition=medium          # 1-10 full nodes, max 3 days
#SBATCH --job-name=pd3_equil
#SBATCH --nodes=1
#SBATCH --ntasks-per-node=40        # MANDATORY for medium partition
#SBATCH --time=00-12:00:00
#SBATCH --output=equil_%j.out
#SBATCH --error=equil_%j.err

set -e
set -x

WORKDIR="/scratch/20ch91r15/GROMACS/single_pd3_water/equilibration"
cd "${WORKDIR}"

source /home/apps/gromacs/gromacs-2022.2/installCPUIMPI/bin/GMXRC.bash
MPIRUN="mpirun -np 40"
GMX="gmx_CPUIMPI"

# ── Phase 1: Energy Minimisation ──────────────────────────────────────────
${GMX} grompp -f 01_em.mdp -c config_mw.pdb -p field.top \
              -n index.ndx -o em.tpr -maxwarn 1

# Single MPI rank + 40 OpenMP threads: EM does not parallelise well
${MPIRUN} ${GMX} mdrun -v -deffnm em -ntmpi 1 -ntomp 40

# ── Phase 2: NVT Equilibration (1 ns) ─────────────────────────────────────
${GMX} grompp -f 02_nvt.mdp -c em.gro -p field.top \
              -n index.ndx -o nvt.tpr -maxwarn 1

${MPIRUN} ${GMX} mdrun -v -deffnm nvt

# ── Phase 3: NPT Equilibration (1 ns) ─────────────────────────────────────
# -t nvt.cpt : inherit NVT velocities — DO NOT omit
${GMX} grompp -f 03_npt.mdp -c nvt.gro -t nvt.cpt \
              -p field.top -n index.ndx -o npt.tpr -maxwarn 1

${MPIRUN} ${GMX} mdrun -v -deffnm npt
```

Submit from the cluster:

```bash
cd /scratch/20ch91r15/GROMACS/single_pd3_water/equilibration
sbatch equilibration.sh
squeue -u 20ch91r15
```

> **PARAM Shakti filesystem policy:** all job I/O must be on `/scratch/$USER`.
> The `/home` path is for source code and configs only. Never run mdrun
> from `/home` — it is not on the fast parallel filesystem.

## 10. Post-Run Sanity Checks

After the job finishes, run the automated sanity-check script:

```bash
bash check_equilibration.sh 2>&1 | tee sanity_report.txt
```

The script checks seven things and prints a coloured PASS / WARN / FAIL for each:

| Check | What it verifies | Pass criterion |
|---|---|---|
| File existence | All 9 output files present | All found |
| Atom count | `.gro` header = 28,823 | Exact match |
| EM convergence | `Maximum force` in `em.log` | Fmax < 1000 kJ/mol/nm |
| NVT temperature | Average last 50% of trajectory | 298.15 ± 5 K |
| NPT density | Average last 50% of trajectory | 997 ± 10 kg/m³ |
| NPT pressure | Average last 50% of trajectory | 1 ± 300 bar |
| Pd–Pd constraint | Distance over NPT trajectory | 0.2676 ± 0.001 nm |

The script also applies the two-step PBC correction automatically:

```bash
# Step A: make all molecules whole (un-wrap across box faces)
gmx trjconv -f npt.xtc -s npt.tpr -n index.ndx \
            -o npt_pbc.xtc -pbc mol -ur compact

# Step B: centre Pd3 in the box (group 2 = pd3, group 0 = System)
echo -e "2\n0" | gmx trjconv -f npt_pbc.xtc -s npt.tpr -n index.ndx \
                              -o npt_center.xtc -pbc mol -center
```

The output `npt_center.xtc` is the trajectory to use for all structural
analysis (RDF, MSD, coordination number, radial density profiles).

> **Step order matters.** Centring before making molecules whole can re-break
> molecules that were just fixed. Always make whole first, then centre.

### Expected equilibration convergence

After a successful equilibration the following properties should be stable
in the last 50% of the NPT trajectory:

| Observable | Expected value | Typical fluctuation |
|---|---|---|
| Temperature | 298.15 K | ± 2–3 K |
| Pressure | 1 bar | ± 100–300 bar (normal for 29k atoms) |
| Density | ~997 kg/m³ | ± 2–3 kg/m³ |
| Pd–Pd distance | 0.2676 nm | < 0.001 nm |

If density is still drifting at the end of 1 ns NPT, extend by another 1 ns
before starting production.

## 11. Proceeding to Production

Once `sanity_report.txt` shows zero FAILs:

```bash
gmx_CPUIMPI grompp \
    -f run.mdp \
    -c npt_center.gro \
    -t npt.cpt \
    -p field.top \
    -n index.ndx \
    -o production.tpr \
    -maxwarn 1
```

Key differences in `run.mdp` versus the NPT mdp:

- `nsteps = 50000000` (100 ns at 2 fs)
- `continuation = yes`, `gen-vel = no`
- `nstxout-compressed = 5000` (every 10 ps → 10,000 frames)
